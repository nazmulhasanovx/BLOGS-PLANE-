# Editorial Operations — Research to Publication

## Status workflow

planned-unpublished -> SERP-reviewed -> outline-approved -> drafting -> technical-review -> copyedit -> SEO-QA -> ready-for-publish -> published -> monitor -> refresh/merge/retire.

NIMORAI product guides start blocked-until-feature-verified, then enter the same workflow only after screenshots, backend evidence and owner signoff.

## Roles

- Content strategist: query intent, cluster placement, overlap checks, scheduling.
- Researcher: current primary docs, competitor matrix, illustrative evidence.
- Subject matter reviewer: correct token/NFT/coin/network and payment facts.
- Writer: unique helpful article and original examples.
- Copy editor: structure, factual wording, language, originality and accessibility.
- SEO editor: links, metadata, search intent, indexability, hreflang.
- Publisher/developer: CMS deployment, technical QA, sitemap.
- Analytics reviewer: Search Console insights and refresh decisions.

## Production steps

1. Select candidate from data/master-600.csv and cross-check feature status.
2. Perform live SERP research; record intent, official sources and content differentiation.
3. Check existing articles and candidate queue for duplicate SERP intent; merge/retire topic if necessary.
4. Build article outline with a unique example, illustration, comparison table or demonstration.
5. Draft with sources; do not write unsupported features, regulatory claims, ROI claims or fabricated stats.
6. Technical subject expert validates definitions, workflows and any example code.
7. Editor checks readability, title/H1 accuracy, links, image rights and fact-vs-proposal labeling.
8. Calculate internal 100-point QA rubric; all hard gates must pass.
9. Create CMS draft, verify actual rendered page, robots/canonical/schema/hreflang/responsiveness.
10. Publish only with explicit human approval; monitor actual indexing and user behavior.
11. Review old content after feature changes, competitor updates or on evidence of stale queries.

## Evidence-first content styles

- Standards: cite authoritative specification or official docs.
- Tutorials: show test environment and reproducible outcome when possible.
- Pricing: date, currency, provider and exact inclusion/exclusion.
- Comparisons: dated first-party source matrix, honest limitations.
- Product help: current UI capture plus engineering-confirmed behavior.
- Safety: explain validation rather than promise invulnerability.
- Localization: edited for language and audience; not machine-stamped duplicates.

## Release controls

The monthly queue in data/24-month-editorial-calendar.csv is a candidate schedule, not an instruction to automatically publish 25 posts regardless of quality. Pause and reassign slots when reviewer capacity, data validation or original evidence is missing.

Never mix draft-only pages into the canonical sitemap.
