# Internal Linking and Topic-Hub Strategy

## Model

A site-level Blog index links to 20 topical hubs. Each hub links to its editorial articles and to related hubs. Each article links contextually to its hub, to 1–3 relevant sibling articles and to 0–2 cross-cluster resources where genuinely useful.

## Pillar architecture

The proposed 20 hub URLs are listed in data/cluster-map.csv. Do not create thin generic hub pages merely to reach a page count. A useful hub should include:
- Distinctive topic intro and useful definitions.
- A visual learning map; clear beginner/intermediate pathways.
- Curated article links in meaningful order; glossary or questions.
- Clear first-party links to product docs only when relevant and true.

## Example contextual journeys

Blockchain basics -> Web3 concepts -> Token standards -> Token creation -> Verification -> Service-delivery explanation.
NFT fundamentals -> Metadata and storage -> NFT creation -> Deployment QA -> Wallet visibility.
Wallet fundamentals -> Transaction hash -> Payment verification -> Billing and support.
Smart contracts -> OpenZeppelin concepts -> Deployment QA -> Security -> Developer API.
Coin vs token -> Coin requirements -> Technical feasibility -> Pricing model and review policy.

## Links NOT to add automatically

- Links to non-published article URLs.
- Generic exact-match anchors repeated in dozens of posts.
- Competitor affiliate or paid links disguised as neutral citations.
- Product landing pages with unavailable features.
- Links simply because a post shares the same cluster tag.

## Link maintenance

Before publish, run a link check and replace proposed URL references with actual canonical destinations. On retire/merge, redirect old URL appropriately and update inbound links. Record the change rather than silently overwriting an article.
